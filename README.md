# Traffic Analysis - Suspicious HTTP POST Investigation

## Overview

This project is based on the PCAP file:

`2026-08-09-traffic-analysis-exercise.pcap`

The purpose of this investigation was to analyze the captured network traffic and identify any suspicious communication from an internal host to an external system.

The investigation was performed using Wireshark.

---

## Alert

During the traffic analysis, repeated HTTP POST communication was observed from the internal host:

`172.16.8.49`

to the external IP:

`146.59.71.167`

The HTTP traffic used the following host:

`www.grinswakebthu.info`

The requests were sent to:

`POST /irpw/ HTTP/1.1`

The repeated POST traffic and the large encoded-looking request body made this communication worth investigating further.

This was treated as a suspicious activity alert, not as confirmed malicious activity at the beginning of the investigation.

## 4. DNS Investigation

DNS traffic was then checked using the following Wireshark filter:

`dns.qry.name contains "firsttolast.tech"`

`firsttolast-dc.firsttolast.tech`

The DNS traffic was documented separately because DNS activity by itself was not enough to classify the host as compromised.

## 5. HTTP Traffic Investigation

After checking the DNS and endpoint information, HTTP traffic from the internal host was investigated.

Wireshark filter used:

`ip.addr == 172.16.8.49 && http`

Several HTTP connections were found.

The traffic included normal-looking GET requests as well as POST requests.

One important connection was:

Source:

`172.16.8.49`

Destination:

`146.59.71.167`

HTTP method:

`POST`

URI:

`/irpw/`

Host:

`www.grinswakebthu.info`

Content-Type:

`application/x-www-form-urlencoded`

The same external destination appeared multiple times in the capture.

Screenshot:

`05-suspicious-http-post.png`

---

## 6. TCP Stream Analysis

The suspicious POST request was followed using:

`Follow -> TCP Stream`

The TCP stream showed:

`POST /irpw/ HTTP/1.1`

Host:

`www.grinswakebthu.info`

Content-Type:

`application/x-www-form-urlencoded`

Content-Length:

`3225`

The request body contained a long encoded/random-looking value.

The stream showed:

`3 client packets, 1 server packet`

The combination of repeated POST requests, the same external destination, the unusual domain and the large request body made the traffic suspicious and justified further investigation.

However, the POST request and encoded-looking data alone do not prove that the traffic was malicious. The evidence was therefore treated as suspicious network activity rather than definitive proof of malware.

# Why This Traffic Was Investigated

The traffic was not considered suspicious because of a single indicator.

The investigation was based on several observations together:

1. An internal host was communicating with an external IP.
2. The communication was repeated.
3. Multiple POST requests were sent to the same external destination.
4. The HTTP URI `/irpw/` was repeatedly used.
5. The external host was `www.grinswakebthu.info`.
6. The POST request contained a relatively large body.
7. The body contained a long encoded/random-looking value.
8. The traffic was therefore worth checking using TCP stream analysis.

These indicators do not independently prove compromise, but together they provide a reasonable basis for a SOC investigation.

# Conclusion

The PCAP contains suspicious HTTP communication originating from the internal host:

`172.16.8.49`

The host repeatedly communicated with:

`146.59.71.167`

using HTTP POST requests to:

`/irpw/`

The requests used:

`www.grinswakebthu.info`

as the Host header and included a large form-urlencoded request body.

The TCP stream showed a long encoded/random-looking value in the POST body.

Based on these observations, the traffic should be considered suspicious and should be investigated further.

The PCAP evidence alone was not used to claim with certainty that the host was infected or that the external server was definitely a command-and-control server.

# Analyst Notes

The main lesson from this investigation was not to label traffic as malicious based on one indicator.

The investigation started with general PCAP statistics, then moved to endpoints and conversations, followed by DNS and HTTP analysis.

The suspicious HTTP connection was then examined at the TCP stream level.

This helped build the finding step by step instead of immediately assuming that every unusual HTTP request was malware traffic.

The strongest indicators found during the investigation were the repeated outbound HTTP POST requests from `172.16.8.49` to `146.59.71.167`, the `/irpw/` URI, the external host `www.grinswakebthu.info`, and the large request body observed in the TCP stream.

Final assessment:

**Suspicious outbound HTTP communication requiring further endpoint and network investigation.**
